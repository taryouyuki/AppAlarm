# アプリ起動アラーム (AppAlarm)

指定した時刻になると「このアプリを開きますか？」というヘッドアップ通知を出し、
タップひとつでそのアプリを起動するAndroidアプリです。

- パッケージ: `com.taryo.appalarm`
- 対応: Android 8.0 (API 26) 以上 / targetSdk 34
- 実機確認: Android 17 (API 37) エミュレータ（Pixel_8 AVD）

## 機能

| 機能 | 内容 |
|---|---|
| 時刻指定 | 24時間表示のタイムピッカー |
| 対象アプリ | 端末にインストールされた起動可能アプリから1つ選択 |
| 繰り返し | 1回だけ / 毎日 / 曜日指定 / 日付指定 / 曜日ごとに時刻を変える |
| 祝日スキップ | 日本の祝日（振替休日・国民の休日を含む）を自動計算して除外 |
| 通知 | 高重要度のヘッドアップ。「開く」「○分後に再通知」の2アクション |
| 再通知の間隔 | アプリ設定（5/10/15/30/60分）＋アラームごとの上書き |
| 再通知の上限 | アプリ設定（1/2/3/5回/上限なし/再通知しない）＋アラームごとの上書き |
| テスト実行 | 保存せずに今すぐ通知・読み上げを確認 |
| 折りたたみ | 繰り返し／通知のしかた／起動のしかた／再通知は閉じたまま概要が見える |
| 通知音 | 標準 / なし / 端末内から選択（試聴つき） |
| 音声読み上げ | あらかじめ入力した文章をTTSで読み上げ（例:「アプリを開く時間です」） |
| 自動オープン | 「開きますか？」を出さずに対象アプリを直接起動（失敗時のみ通知） |
| アラーム鳴動 | 画面点灯＋アラーム音＋「停止／スヌーズ」（full-screen intent） |
| アラーム音 | アラーム鳴動時に鳴らす音を端末内から選択（既定は端末のアラーム音） |
| 外観 | システム／ライト／ダーク。Android 12+ では Material You の壁紙色をアクセントに使用 |
| ウィジェット | ホーム画面に「次のアプリと時刻」を表示。タップでアプリを開く |
| バックアップ | 設定をJSONで書き出し／復元 |
| 再スケジュール | 再起動・時刻変更・タイムゾーン変更・アプリ更新時に自動で復元 |

作者: **achi**（`com.taryo.appalarm.AUTHOR` メタデータに記載。画面には表示しません）

## インストール

```powershell
adb install -r build\AppAlarm.apk
```

初回起動時に次の2つを許可してください。

1. **通知**（Android 13+）— ダイアログで「許可」
2. **アラームとリマインダー**（Android 12+）— アプリ内の案内から設定画面へ

## ビルド

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
# -> build\AppAlarm.apk
```

Gradle ではなく SDK の build-tools を直接叩いています。理由:

- このPCの JDK が 26 のみで、キャッシュ済みの Gradle 8.7 / AGP 8.5.2 と噛み合わない
- シェルからの HTTPS 通信が遮断されており、Maven から依存を取得できない

そのため外部ライブラリ（AndroidX 等）は使わず、フレームワークAPIのみで完結させています。
画面も XML レイアウトではなくコードで構築しているので、リソースは不要です。

処理の流れ: `javac`（android.jar を bootclasspath に指定）→ `d8`（build-tools 36.1.0）
→ `aapt package`（build-tools 34.0.0）→ `aapt add classes.dex` → `zipalign` → `apksigner`。

> 注意: build-tools 34.0.0 の d8 (8.2.2) はこのクラスファイルで NPE を起こすため、
> dex のみ 36.1.0 の d8 を使っています。

## 祝日計算について

固定日・ハッピーマンデー・春分/秋分（1980〜2099年で有効な近似式）から祝日を作り、
**振替休日**（日曜と重なった場合）と**国民の休日**（祝日に挟まれた1日）も算出します。

```powershell
javac -d test\out src\com\taryo\appalarm\JapaneseHolidays.java test\HolidayCheck.java
java -cp test\out HolidayCheck   # 2026年18日 / 2027年17日 を検証
```

## 通知のアクション

- **開く** — 対象アプリを起動します（通知は閉じます）
- **5分後に再通知** — 今の通知を閉じ、5分後に同じプロンプトをもう一度出します。
  このとき通常のスケジュール（毎日／曜日指定）は変更しません。

## 通知音と読み上げ

| モード | 動作 |
|---|---|
| 標準の通知音 | 端末の既定通知音＋バイブ |
| 通知音なし | 無音・バイブなし（サイレントチャンネル） |
| 通知音を選ぶ | 端末内の通知音／アラーム音から選択（選ぶと試聴します） |
| 音声で読み上げ | 入力した文章をTTSで読み上げ。通知自体は無音 |

読み上げは `USAGE_NOTIFICATION` のオーディオ属性で再生するため、**端末の通知音量**で大きさが変わります
（メディア音量ではありません）。

Android 8以降は通知チャンネルが音を保持するため、音の設定ごとにチャンネルを作り分けています
（設定を変えると古いチャンネルは自動削除されます）。

読み上げは `VoiceService`（フォアグラウンドサービス）で実行します。TTSの初期化に失敗した場合は
無音のまま通知だけが出ます。

## 自動オープンについて

「確認せずに自動で開く」をオンにすると、時刻になった瞬間に対象アプリを直接起動します。

Android 10 以降はバックグラウンドからの画面起動が制限されていますが、
**「他のアプリの上に重ねて表示」（SYSTEM_ALERT_WINDOW）** を許可したアプリは免除されます。
そのため初回に一度この許可を求めるダイアログが出ます。

許可しなかった場合は、これまで通り通知で確認する動作にフォールバックします
（ログでは `Abort background activity starts` が出ます）。

> 画面ロック中は、端末やOSのバージョンによって起動が拒否されることがあります。
> その場合も通知が表示されます。

## 曜日ごとの時刻

「曜日ごとに時刻を変える」を選ぶと、月〜日の7行にそれぞれ時刻を設定できます。
例: 月〜金 07:00 / 土日 09:00。×でその曜日だけ解除できます。

一覧には `月火水木金 07:00・土日 09:00` のようにまとめて表示されます。

## 全画面通知

「ロック画面では全画面で表示する」をオンにすると、画面ロック中でも対象アプリの画面が開きます
（`setFullScreenIntent`）。Android 14 以降で許可されていない場合は通知にフォールバックします。

## ウィジェット

ホーム画面のウィジェット一覧から「アプリ起動アラーム」を選んで配置してください。
次のアラームの時刻とアプリ名を表示し、タップでアプリが開きます。

## バックアップと復元

設定画面から、アラーム設定をJSONで書き出せます。保存先は
`/sdcard/Android/data/com.taryo.appalarm/files/` です。復元は同じ場所のファイルから選びます。

## フローティングウィンドウ

「起動のしかた」に「フローティングウィンドウで開く」を追加しました。
Android の開発者向けオプション「**アクティビティをサイズ変更可能にする**」
（`Settings.Global.force_resizable_activities`）または「フリーフォーム ウィンドウを有効にする」
（`enable_freeform_support`）が無効な端末では、この項目は自動的にグレー表示になります。

> 制限（重要）: 通常のアプリから他アプリをフローティング表示にすることは、Android では**できません**。
> 窓の種類を指定する `ActivityOptions.setLaunchWindowingMode` は公開SDKに存在せず、
> リフレクションでも `NoSuchMethodException` で拒否されます（Android 17 / SDK 37 で確認）。
> `setLaunchBounds` だけ指定しても無視され、通常の全画面で開きます。
> 開発者向けオプションをオンにしても、アプリ側から強制する手段がないのが実情です。
> そのためこのトグルは「OS側の設定が入っているかを検出して、使えないときはグレーにする」までを担当します。
> 通知を出さずに開きたい場合は、次の全画面通知を使ってください。

## アイコン

`tools/make_icon.py`（Pillow）で生成しています。パステルのカレンダーに再生ボタンを重ねた、
背景透過のアイコンです。ランチャーによっては白い円形の背景が付きます（Android の仕様）。

## 実機（Pixel 8）へのセットアップ

```powershell
adb install -r AppAlarm.apk
adb shell pm grant com.taryo.appalarm android.permission.POST_NOTIFICATIONS
adb shell appops set com.taryo.appalarm SCHEDULE_EXACT_ALARM allow
adb shell appops set com.taryo.appalarm SYSTEM_ALERT_WINDOW allow   # 制限付き設定を回避
```

「アプリはアクセスを拒否されました」と出る場合は、UIから許可する代わりに
`appops set ... SYSTEM_ALERT_WINDOW allow` を adb から実行すれば通ります。

## 実機で「重ねて表示」が許可できないとき

Android 13 以降、APKを直接入れた（ストア以外の）アプリは「制限付き設定」で保護されており、
「他のアプリの上に重ねて表示」をオンにしようとすると
**「アプリはアクセスを拒否されました」** と表示されます。

対処: **設定 → アプリ → アプリ起動アラーム → 右上の ⋮ → 「制限付き設定を許可」** をオンにしてから、
もう一度「重ねて表示」を有効にしてください。

この許可を使わずに通知なしで開きたい場合は、**「ロック画面の上にアプリの画面を出す」**（全画面通知）が
代わりに使えます。こちらは追加の許可が要りません。

## アラーム鳴動モード

「アラームとして鳴らす（停止 / スヌーズ）」をオンにすると、目覚まし時計のように動きます。

1. 時刻になると**画面が点灯**（SCHEDULE_EXACT_ALARM + SCREEN_BRIGHT_WAKE_LOCK）
2. **アラーム音がループ再生**（`USAGE_ALARM` ストリームなのでマナーモードでも鳴る）
3. **「停止」「スヌーズ」**を表示
   - 停止 → 音を止めて対象アプリを起動
   - スヌーズ → 音を止め、設定した間隔（既定10分）でもう一度鳴らす

> 画面が点いている（ロックしていない）とき、Android は全画面通知を「ヘッドアップ通知」に
> 格下げするため、アラーム画面が出ないことがあります。
> そのため「重ねて表示」権限がある場合は、通知に頼らずアプリから直接アラーム画面を起動します。

ロック中の場合は、停止したあとロックを解除するとアプリが開きます
（PIN・指紋がある場合、解除には本人認証が必要です。これは Android の仕様です）。

## 既知の制限

- **エミュレータのタイムゾーンに注意**。AVDは既定で GMT のことがあり、日本時間より9時間ずれます。
  `adb shell cmd alarm set-timezone Asia/Tokyo` で直せます（アプリ側は端末のローカル時刻に従うので、これは環境の問題です）。
- **ヘッドアップ通知は画面ロック中には出ません**（ロック画面の通知として残ります）。
  ロック中でも必ずポップアップさせたい場合は、全画面インテント通知かオーバーレイ表示への変更が必要です。
- Android 14 以降、`SCHEDULE_EXACT_ALARM` は初期状態で拒否されています。アプリ内の案内から許可してください。
- 端末の省電力設定（メーカー独自の最適化）が強いと、発火が数分遅れることがあります。
- 対象アプリがアンインストールされている場合、通知は「見つかりません」と表示されます。
- Google Play 配布用の設定（リリース署名・難読化）はしていません。デバッグ署名です。
